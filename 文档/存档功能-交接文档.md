## 2. 已查实的事实（代码现状）

### 2.1 数据层：`app/src/lib/profileStore.js`
- localStorage 单键存储：`nikke-photos/profile/v1`
- 单档结构：`{ version, updatedAt, characters: { [nameCode]: record } }`
- 对外 API（页面全部依赖，重构时保持签名不变）：
  - `loadStore()` / `saveStore(store)`
  - `loadRecord(nameCode)` / `saveRecord(nameCode, record)` / `removeRecord(nameCode)`
  - `recordedCodes()` / `countRecords()`
  - `exportProfile()`（整档 JSON 字符串）/ `importProfile(text)`（覆盖本机档案，校验角色键，返回 `{ imported, unknown }`）

### 2.2 使用点（实施时需全部兼容，且页面代码尽量零改动）
| 文件 | 用到的 API | 场景 |
| --- | --- | --- |
| `app/src/pages/CharacterListPage.jsx` | `recordedCodes`、`exportProfile`、`importProfile` | "已录入 N 名"、导出档案 / 导入档案（含覆盖二次确认） |
| `app/src/pages/CharacterPage.jsx` | `loadRecord`、`saveRecord` | 打开装档、离开时兜底保存 |
| `app/src/pages/DataEntryPage.jsx` | `loadRecord`、`saveRecord`、`removeRecord` | 录入 / 即时保存 / 清除本机数据；左侧"已录入"标记 |
| `app/src/pages/StatsPage.jsx` | `loadRecord` + `statsModel.isFullyRecorded` | 统计表；`isFullyRecorded` = 四件装备全录入，可作为"已完善：N"的现成口径 |

### 2.3 UI / 路由现状
- `app/src/components/TopNav.jsx`：`topbar → topbar-inner → brand / tabs（角色列表、数据录入、我的）/ topbar-right`；`topbar-right` 目前仅 `<span>v0.1</span>`
- `app/src/pages/MyPage.jsx`（/my）：入口卡片数组 `ENTRIES`（现仅"词条统计"→ /stats）；样式类 `.my-grid` / `.my-card` 定义在 `app/src/styles/stats.css`
- 路由：HashRouter（`app/src/App.jsx`）
- 子页返回模式参考 /stats：「返回上一级」按钮用 `location.key !== 'default' ? navigate(-1) : navigate('/my')`

### 2.4 已定技术方案（上一窗口已研究定案，不必再问用户）
- profileStore **内部改为多存档存储**：存档索引（名称、id、当前存档 id）+ 每档独立数据；**对外 API 签名保持不变**，内部读写一律作用于"当前存档"，四个页面代码几乎不用改
- 旧数据（`nikke-photos/profile/v1`）**自动迁移**为「默认存档」：固定 id、不可删除
- 存储键布局（示例，由实施窗口定）：索引 `nikke-photos/profiles/v1/index` + 每档 `nikke-photos/profiles/v1/data/<id>`；或单键多档结构

❓ **Q1 - 存档管理页的切换与操作交互**：点击某存档行 = 切换为当前存档？新建后自动切到新档？删除"当前存档"时自动切回默认档？删除是否需要二次确认？改名用行内输入还是弹窗？存档数量是否设上限？名称是否允许重复？

---

❓ **Q2 - "已完善：N"的定义**：已录入角色数（有任意记录就算）还是四件装备全录入数（与词条统计页"可统计"同口径）？

➡️ 推荐：与统计页同口径 = 四件装备全录入（复用 `statsModel.isFullyRecorded`）。理由：用户提到"已完善"，语义更接近"这个角色的数据填完了"。

---

❓ **Q3 - 列表页「导出档案 / 导入档案」在多存档下的作用域**：仅针对当前存档，还是对应全部存档（如导出全部、或让用户选择）？

➡️ 推荐：仅针对"当前存档"——导出当前档；导入覆盖当前档（覆盖确认文案里带上存档名，避免歧义）。

---

❓ **Q4 - 顶部"当前存档：xxx"是否可点击**：不可点（纯展示）还是点击跳转存档管理页？

➡️ 推荐：可点击，跳转存档管理页。

---

❓ **Q5 - 切换存档后各页面数据刷新策略**：是否需要特殊处理（如提示重载、清空页面内缓存）？

➡️ 推荐：无特殊处理——各页挂载时自然读取当前档；数据录入页为即时保存、无未保存态，切档不会丢数据；角色列表页的筛选状态存 sessionStorage（与存档无关），保留不动。

---

❓ **Q6 - 存档管理页概览的展示字段确认**：每个存档行展示 = 名称 + "已完善：N" + 当前标记 + 操作（改名 / 删除 / 设为当前）？默认存档初始名"默认存档"，可改名但不可删除？

➡️ 推荐：按上述字段展示；默认档初始名"默认存档"、可改名、不可删除（删除按钮置灰或隐藏）。
