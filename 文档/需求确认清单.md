## 3. 数据模型

- **单账号档案 profile（仅一个）→ 内含多角色记录 records**，记录键 = `name_code`
- 角色记录字段 = 卡片模型：
  - 稀有度、突破（grade 0~3 / core）
  - 等级 + 等级上限、名称 + 称号（如"桃乐丝：机缘巧遇"）
  - 好感度（RANK）、战斗力
  - 属性图标组：职业 / 企业 / 元素 / 爆裂阶段 / 武器
  - 研究所：职业等级（如 LV.153）+ 企业等级（如 LV.130）
  - 技能三档（1/2/爆发）、魔方（id + 等级）
  - 收藏品/爱用品（稀有度 + 等级）
  - 4 件装备：类型 + 等级 + 3 条词条（名称 / 档位 / 数值 / 是否"未获得"）
- 派生计算：**词条合计**（档位合计、百分比、条数计数）由装备词条自动汇总；其余数值一律手填（v1 不做自动计算）
- 存储：localStorage 自动存草稿 + JSON 手动导入/导出

## 4. 角色卡（M2 交付）

- 设计尺寸 736×1096（CSS px），与 Workshop 版式对齐
- 导出弹窗：倍率 1x / 2x / 3x（**默认 3x = 2208×3288**）、PNG、白底/透明、署名开关 + 文本（默认关）、文件名 `NIKKE_{角色名}_{皮肤}_{yyyyMMdd-HHmm}.png`
- **10 个模块开关（默认全开）**：收藏品 / 稀有度·突破 / 等级·名称 / 好感度 / 战斗力 / 属性图标 / 技能等级 / 魔方 / 词条合计 / 四件装备
- 缺数据策略：该模块整块隐藏；无立绘时占位且数值/图标照常、仍可导出
- 立绘：由 catalog 驱动，可选**默认（原皮）与皮肤（自带中文名，如"反派赛车手"）**；支持拖拽位置 + 缩放（70~180%）+ 一键复位
- 装备槽：沿用《装备图渲染规格》（红色四边渐变、2×2、90×90 帧）
- 字体：v1 用系统字体栈；字体收敛为单一入口（CSS 变量 + `fonts/` 目录），M4 换解包字体；词条区独立组件，M4 可换 PNG 字模

## 5. 角色列表（M1 交付物）

数据源（均由构建脚本生成，可复跑、可校验）：

| 用途 | 来源 |
|---|---|
| 名单与分类字段 | `E:\桌面\NIKKE Helper\NIKKE-LocalAssets\data\nikke-directory.json`（201 条） |
| 头像与立绘变体 | 同目录 `character-assets.json`（201 角色 / 头像 201 / 立绘 379） |
| 国服名单 + 国服译名 | 同目录 `cn-roster.json`（cnRoster + displayNames） |
| 珍藏品 / 超标准 | 同目录 `tags.json` |
| 立绘补全集（M2 用） | Workshop `characterArtworkCatalog.json`（202 角色 / 623 张，含珍藏品背景、技能动画静态图） |

行为定义：

- 主键 `name_code`；搜索支持中文名 / 英文名 / 资源号 / 拼音首字母；国服译名折叠为别名，不新占条目
- **6 组分类（照抄 NIKKE Helper，含选项原值）**：企业 `ELYSION/MISSILIS/TETRA/PILGRIM/ABNORMAL`、爆裂阶段 `Step1/Step2/Step3/AllStep`、武器 `AR/MG/RL/SG/SMG/SR`、稀有度 `SSR/SR/R`、属性 `Fire/Water/Wind/Electronic/Iron`、职业 `Attacker/Defender/Supporter`；组内多选 OR、跨组 AND
- **3 个开关**：国服已实装（默认关，开启=只显示国服名单，JSON 管理）/ 珍藏品 / 超标准
  - 珍藏品口径：**全集 21 人**（数据来自 NIKKE Workshop `characterObjectAssets.json` 的 favorites 名单，素材经解包 `mi_favoriteitem_cNNN_00` 校验）；其中"国服已实装珍藏品 12 人"存为数据字段 `collectibleCn`
  - 叠加规则：`国服已实装` 单独开启 = 角色口径（143 人）；`珍藏品 + 国服已实装` 同时开启 = 国服已实装珍藏品（12 人）
- 默认范围：显示全部角色
- 展示：头像网格 + 名字 + 分类小图标；缩放控件（放大 / 中 / 缩小）
- 空态与缺图：无匹配给提示；缺头像用占位底

## 7. UI 设计契约（摘要）

- **浅色为主**（深色模式列后续规划）；主色为 NIKKE 橙 `#E8611C` 系，仅用于主按钮 / 选中 / 当前 Tab / 关键信息
- 令牌 7 类：主背景 / 次背景 / 边框 / 主文字 / 次文字 / 主色 / 状态色（成功·警告·错误）
- 细边框优先、阴影仅用于浮层/弹窗/下拉；圆角分级（容器中、按钮与输入中小、标签略圆）
- 文字层级：页面标题 / 区域标题 / 正文 13–14px / 辅助 12px / 次要 11–12px；不写无意义填充文案
- 动画 100–200ms（Tab、悬停、弹窗、状态变化）；桌面优先，窄屏换行不崩
- 禁止项：紫蓝渐变、巨大胶囊按钮、满屏阴影或毛玻璃、卡片堆叠、装饰图标滥用、营销页式 CTA

### OCR 模块（探索结果，2026-10-01）

- 已实现：`src/lib/ocr/core.js`（二值化 / 连通域 / 模板分类 / 数字段扫描）+ `scripts/ocr-scan.mjs`（Node 端 CLI，支持 `--ink/--threshold/--min-score/--region/--components/--dump/--digit-dir/--json`）+ 模板同步（Workshop `public/ocr` 242 个文件已进 `public/ocr`）
- 验证 A（档位数值表，affix 字模）：15 行数值全部定位，13/15 完全正确（单字置信 0.72~0.82）
- 验证 B（参考1 角色面板）：所有数字区域都能定位，但逐字识别不可靠——**该面板使用游戏展示字体（窄体方块字），与 affix 模板字形不同**（对比图见 `文档/_ocr_dump_ref1.png` 与 `文档/_ocr_templates.png`）
- 结论：装备词条类（affix 字体）可直接用现有模板；角色面板类需要**该字体的字模**，优先方案是用解包字体渲染生成模板，或用带真值的截图自动切字

### 字体对应关系（已用解包字体库验证，2026-10-01）

字体库位置：`D:\NIKKE备用工作区0923_tools\font_library\`（40 个唯一字体 + `manifest.csv` + `docs\FONT_LIBRARY.md`）

| 界面元素 | 字体 | 内部名 | 验证方式 |
